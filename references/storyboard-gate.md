# storyboard-gate — 镜头稿放行门槛（本地扩展）

镜头稿交给用户之前，逐条过本文件；任一项不过，先改稿再交。适用于所有模式（自主创作也要在
设计 spec 里留下本表的自检结果）。本文件与 `opus55-methods-2026-09.md` §5（三幕结构）、
审美准则 C4（主张可追溯）配合使用。

## 1. 先写定位，再写镜头

镜头稿第一页固定写四行，缺一行不开始排镜头：

| 项 | 要求 |
|----|------|
| 片种 | 故事片 / 功能演示 / 版本更新 三选一；用户说“要故事感、不是功能展示”时只能是故事片 |
| 观众 | 具体到角色（如“品牌老板、投流负责人、招商对象”），决定用谁的语言说话 |
| 一句话 | 看完只记住的那句话；必须能被产品方法论或实现证据支撑 |
| 那根线 | 贯穿全片的视觉意象，优先取产品方法论自带的比喻（如“双轮”“刹车线”） |

## 2. 卖点台账：每个镜头绑一个核心卖点

- 先从**产品方法论原文**（不是从页面清单）提炼 5–7 条核心卖点，写明出处（文件+章节）。
- 每个镜头只绑一条卖点；绑不上的镜头删除。**页面上有的功能 ≠ 卖点**。
- 每条卖点再标实现证据（源码/界面文案/验收记录）。只有方法论、没有实现的，只能作为理念旁白，
  不能做成“软件正在执行”的画面。

## 3. 禁止上镜的内容（判例见审美准则 C5）

1. **让产品显得手动、费力的操作**：逐项勾选、手动导入、表格核对、填表单。这些是投手的负担，
   不是卖点；需要交代数据来源时用一个抽象的“数据汇入”意象带过，不超过 2 秒。
2. **次要机制当主角**：约束选项、保留余额、预算模式开关之类的实现细节不做单独镜头、不进字幕。
3. **错误或降级的方法描述**：旁白和字幕对算法的描述必须与实现一致（例如本项目是分层饱和响应
   曲线 + 参数抽样 + 下尾风险 + 约束求解，不能说成“按历史响应分配”）。写前先读数学/算法文档。
4. **空洞的技术腔或自夸词**：“AI 智能策略”“每条结论都能回指依据”这类开发者视角的说法。
   改成观众能感到的结果（“哪里坏了，说得出原因，也拿得出证据”）。
5. 无证据的效果数字、客户 logo、收益承诺、自动执行暗示（C4 不变）。

## 4. 故事检查

- 三幕比例：处境 15–20% / 转折 55–65% / 回报 15–20%。处境段不出现产品 UI。
- 主角是真实用户角色，处境是方法论里写明的真实痛点（附出处），不是编的戏剧冲突。
- 界面画面总时长 ≤ 全片 40%；其余用意象、数据可视化、公式、字卡讲。界面只作“证据”出现，
  每次出现都回答“那根线此刻变成了什么”。
- 允许炫技（公式墙、3D 曲线、粒子、数字滚动），但炫技画面里的公式/数字必须取自产品真实文档
  或实现，禁止装饰性假公式。

## 5. 文案检查

- 旁白一句 ≤22 字、只讲一件事；用观众的行话（投手、老板），不用源码字段名。
- 字卡不重复旁白原句；全片同一句口号只出现一次。
- 每句旁白在台账里能指到一条卖点与出处。

## 6. 镜头稿交付格式

1. 定位四行（§1）。
2. 卖点台账：`| # | 卖点 | 方法论出处 | 实现证据 | 用在第几镜 |`。
3. 分镜表：`| # | 时间 | 幕 | 画面 | 动效/镜头卡 | 旁白 | 字卡 | 声音 | 绑定卖点 |`。
4. 所需素材与风险：哪些镜头要真实截图、需要哪些脱敏演示数据、哪些镜头卡需新写。
5. 本文件逐条自检结果（✓/✗ 与处理）。
6. 待用户决定的事项（≤3 条）。
